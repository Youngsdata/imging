3단계로 완료

내보내기 전에 중요한 설정을 확인하세요. 처리 위치는 항상 공개됩니다.

01

HTML 또는 페이지 폴더 선택

즉시 미리 볼 수 있도록 자체 포함된 파일 하나를 선택하거나 관련 CSS, 이미지, 글꼴, 스크립트 또는 데이터가 포함된 경우 전체 폴더를 승인하세요.

02

실제 페이지 기하학 준비

@page 크기, 방향, 여백 및 페이지 매김을 유지합니다. @page를 사용하지 않으면 렌더링된 전체 웹 페이지를 하나의 사용자 정의 PDF 페이지로 만듭니다.

03

무손실 생성, 최소화 및 저장

Chromium은 실제 PDF 바이트를 렌더링한 다음 페이지, 텍스트 및 링크 확인 전에 이미지를 리샘플링하지 않고 동일한 벡터 경로와 보이지 않는 문자 모양 그림을 압축합니다.

페이지를 이미지로 병합하는 대신 Chromium을 사용하는 이유는 무엇입니까?

HTML의 최종 모습은 CSS 레이아웃, 웹 글꼴, SVG, 캔버스, 페이지 규칙, 링크 및 브라우저 조판에서 비롯됩니다. DOM에서 캔버스로 병합하면 선택 가능한 텍스트, 벡터 및 링크가 손실되는 반면 부분적인 CSS 재구현은 웹 플랫폼을 포함할 수 없습니다. 따라서 ImgIng은 Chromium의 자체 인쇄 엔진과 Skia PDF 출력을 사용하여 실제 PDF 바이트를 반환합니다.

페이지가 더 이상 A4로 강제 표시되지 않는 이유는 무엇입니까?

HTML의 실제 페이지를 따르는 것이 기본값입니다. @page가 존재하면 ImgIng는 크기, 방향, 여백 ​​및 페이지 매김을 유지합니다. @page가 없는 연속 웹 페이지는 최종 렌더링된 너비와 높이를 하나의 사용자 정의 PDF 페이지로 사용합니다. ImgIng PDF에서 HTML로 내보낸 고정 레이아웃 HTML은 페이지별 기하학을 전달하므로 라운드트립은 혼합 페이지 크기를 포함하여 모든 소스 페이지를 복원합니다. A4 및 Letter는 명시적으로 선택한 경우에만 적용됩니다.

변환 후에는 어떻게 되나요?

오른쪽 패널에는 자산 매핑, 글꼴 및 동적 렌더링 준비, Chromium PDF 생성, 무손실 최소화, 선택한 위치에 쓰기 등 5가지 연속 단계가 표시됩니다. 준비 리스너는 준비된 페이지가 로드되기 전에 설치되므로 빠른 페이지는 준비 메시지를 놓치거나 잘못된 시간 초과를 기다릴 수 없습니다.

일반적인 무손실 최소화는 어떻게 작동하나요?

최적화 프로그램은 하나의 차트 라이브러리 또는 하나의 SVG 레이아웃을 인식하지 못합니다. 일반 HTML, SVG, 캔버스, 중국어 및 라틴 글꼴과 혼합 페이지에서 생성된 PDF 컨텐츠 스트림에서 작동합니다. 각 호출자가 변환, 색상, 알파 및 클리핑 상태를 유지하는 동안 수학적으로 동일한 채워진 경로가 공유 PDF 양식 개체로 승격됩니다. 보이는 글꼴은 그대로 유지됩니다. 모든 사용이 눈에 띄지 않는 것이 입증된 유형 3 글리프 그림만 원래 측정항목으로 축소됩니다. 이미지는 자동 사전 설정에서 리샘플링되거나 다시 인코딩되지 않습니다. 페이지 상자, 선택 가능한 텍스트 연산자 및 링크는 나중에 다시 읽혀지며 불일치가 있으면 원본 Chromium 파일이 반환됩니다.

PDF-HTML-to-PDF 왕복이 여전히 더 클 수 있는 이유는 무엇입니까?

고정 레이아웃 HTML 내보내기에는 보이는 SVG 윤곽선과 보이지 않는 선택 가능한 텍스트 레이어가 모두 포함될 수 있습니다. Chromium은 두 레이어를 모두 다시 패키징해야 합니다. 무손실 재사용은 많은 양의 반복된 그리기를 제거하지만 레이어를 삭제하거나 벡터를 래스터화하거나 글꼴을 교체하면 정보가 삭제됩니다. 따라서 ImgIng은 성능 저하로 인해 소스 바이트 크기에 강제로 적용되는 것이 아니라 실제 결과를 보고합니다.

무엇이 로컬에 남아 있고 무엇이 제출됩니까?

파일 선택, 페이지 폴더 읽기, 즉시 미리보기, 로컬 CSS, 이미지 및 글꼴 매핑, 허용된 로컬 스크립트를 별도로 실행, 최종 보기 설정 및 PDF 최적화가 브라우저에 남아 있습니다. 변환 시 고정된 자체 포함 스냅샷만 좁은 범위의 동일 출처 Chromium 프로세스에 제출됩니다. 원격 리소스는 기본적으로 차단되고, 요청이 끝나면 임시 파일이 삭제되며, 렌더러는 외부 호스트를 확인할 수 없습니다.

베타 한도: 유난히 긴 한 페이지 문서는 Chromium의 안정적인 페이지 크기 한도에 비례하여 맞춰집니다. ES 모듈, 서비스 워커, 확장 페이지, DRM 미디어, 중첩된 iframe 및 로그인된 교차 원본 리소스 내부의 상대 가져오기는 안정적으로 재현할 수 없습니다. 이 서비스는 최대 64MB의 스냅샷을 허용하고 동시성 및 렌더링 시간을 제한합니다. 전환하기 전에 센터 미리보기 및 품질 보고서를 검토하세요.

자주 묻는 질문

이러한 눈에 보이는 답변은 현재 제품 동작 및 구조화된 데이터와 일치합니다.

HTML 및 로컬 자산이 즉시 업로드됩니까?

아니요. 가져오기, 폴더 읽기, 리소스 매핑 및 전체 미리 보기는 로컬에 유지됩니다. 변환을 클릭하기만 하면 고정된 스크립트 없는 스냅샷이 동일 원본 PDF 렌더러에 제출되며 요청 후 임시 파일이 삭제됩니다.

자동 최소화로 인해 이미지, SVG 또는 글꼴이 변경됩니까?

아니요. 기본 사전 설정은 이미지를 리샘플링하거나 표시되는 글꼴을 변경하지 않습니다. 수학적으로 동일한 벡터 경로만 공유하고 모든 사용이 눈에 띄지 않는 경우에만 문자 모양 그리기를 압축합니다.

프린터, PDF 재선택 또는 별도의 압축 단계가 필요합니까?

아니요. 반환된 PDF 바이트는 손실 없이 최소화되고 페이지, 텍스트 및 링크 의미를 다시 읽은 다음 직접 저장됩니다. 손실이 있는 인쇄, 전자책 및 화면 사전 설정은 명시적인 선택으로 남아 있습니다.
