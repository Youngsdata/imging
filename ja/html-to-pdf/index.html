3ステップで完了

エクスポートする前に重要な設定を確認してください。処理場所は常に開示されます。

01

HTML またはページ フォルダーを選択してください

即時プレビュー用に自己完結型ファイルを 1 つ選択するか、相対的な CSS、画像、フォント、スクリプト、またはデータが関係する場合はフォルダー全体を承認します。

02

実際のページのジオメトリを準備する

@page のサイズ、向き、余白、ページネーションを維持します。 @page を使用しないと、完全にレンダリングされた Web ページが 1 つのカスタム PDF ページになります。

03

ロスレスで生成、最小化、保存

Chromium は実際の PDF バイトをレンダリングし、ページ、テキスト、リンクの検証前に画像をリサンプリングすることなく、同一のベクトル パスと明らかに目に見えないグリフ描画を圧縮します。

ページを画像にフラット化するのではなく、Chromium を使用するのはなぜですか?

HTML の最終的な外観は、CSS レイアウト、Web フォント、SVG、Canvas、ページ ルール、リンク、ブラウザーの植字によって決まります。 DOM からキャンバスへのフラット化では、選択可能なテキスト、ベクター、リンクが失われますが、部分的な CSS の再実装では Web プラットフォームをカバーできません。したがって、ImgIng は、Chromium 独自の印刷エンジンと Skia PDF 出力を使用して、実際の PDF バイトを返します。

ページが強制的に A4 に収まらなくなったのはなぜですか?

HTML の true ページがデフォルトであることに従う。 @page が存在する場合、ImgIng はそのサイズ、方向、余白、ページネーションを保持します。 @page のない連続 Web ページは、最終的にレンダリングされた幅と高さを 1 つのカスタム PDF ページとして使用します。 ImgIng PDF to HTML によってエクスポートされた固定レイアウト HTML はページごとのジオメトリを保持するため、ラウンドトリップにより、混合ページ サイズを含むすべてのソース ページが復元されます。 A4 とレターは、明示的に選択された場合にのみ適用されます。

変換後はどうなりますか?

右側のパネルには、アセット マッピング、フォントと動的レンダリングの準備、Chromium PDF 生成、ロスレス最小化、選択した場所への書き込みという 5 つの連続した段階が表示されます。 Readiness リスナーは、準備されたページが読み込まれる前にインストールされるため、高速ページが Ready メッセージを見逃して誤ったタイムアウトを待つことができません。

一般的な可逆最小化はどのように機能しますか?

オプティマイザは、1 つのグラフ ライブラリまたは 1 つの SVG レイアウトを認識しません。通常の HTML、SVG、Canvas、中国語、ラテン語のフォント、および混合ページから生成された PDF コンテンツ ストリームで動作します。数学的に同一の塗りつぶされたパスは、各呼び出し元がその変換、色、アルファ、およびクリッピング状態を維持しながら、共有 PDF フォーム オブジェクトにプロモートされます。表示されているフォントはそのまま残ります。すべての使用が明らかに不可視であるタイプ 3 のグリフ描画のみが、元のメトリクスに縮小されます。自動プリセットでは、画像は再サンプリングまたは再エンコードされません。ページ ボックス、選択可能なテキスト演算子、およびリンクは後で再読み取りされ、不一致がある場合は元の Chromium ファイルが返されます。

PDF から HTML へ、そして PDF へのラウンドトリップがさらに大きくなるのはなぜですか?

固定レイアウトの HTML エクスポートには、表示される SVG アウトラインと非表示の選択可能なテキスト レイヤーの両方が含まれる場合があります。 Chromium では両方の層を再度パッケージ化する必要があります。ロスレス再利用では、大量の繰り返し描画が削除されますが、いずれかのレイヤーを削除したり、ベクターをラスタライズしたり、フォントを置き換えたりすると、情報が破棄されてしまいます。したがって、ImgIng は、劣化によってソース バイト サイズに強制されるのではなく、実際の結果を報告します。

何がローカルに残り、何が提出されるのでしょうか?

ファイルの選択、ページ フォルダーの読み取り、インスタント プレビュー、ローカル CSS、画像、フォントのマッピング、許可されたローカル スクリプトの個別実行、最終ビューの設定、PDF の最適化はブラウザー内に残ります。 Convert では、凍結された自己完結型スナップショットのみが、範囲が狭い同一オリジンの Chromium プロセスに送信されます。リモート リソースはデフォルトでブロックされ、リクエストが終了すると一時ファイルが削除され、レンダラーは外部ホストを解決できません。

ベータ版の制限: 非常に長い 1 ページのドキュメントは、Chromium の安定したページ サイズの上限に比例して収まります。 ES モジュール、Service Worker、拡張ページ、DRM メディア、ネストされた iframe、サインインされたクロスオリジン リソース内の相対インポートは、確実に再現できません。このサービスは最大 64 MB のスナップショットを受け入れ、同時実行性とレンダリング時間を制限します。変換する前に、中央のプレビューと品質レポートを確認してください。

よくある質問

これらの目に見える答えは、現在の製品の動作と構造化データと一致します。

HTML とローカル アセットはすぐにアップロードされますか?

いいえ。インポート、フォルダーの読み取り、リソースのマッピング、および完全なプレビューはローカルに残ります。 「変換」をクリックするだけで、フリーズされたスクリプト不要のスナップショットが同じオリジンの PDF レンダラに送信され、リクエスト後に一時ファイルが削除されます。

自動最小化により画像、SVG、フォントは変更されますか?

いいえ。デフォルトのプリセットは画像をリサンプリングしたり、表示されるフォントを変更したりしません。数学的に同一のベクトル パスのみを共有し、すべての使用が目に見えないことが証明されている場合にのみグリフ描画を圧縮します。

プリンター、PDF の再選択、または別の圧縮手順が必要ですか?

いいえ。返された PDF バイトはロスレスで最小化され、ページ、テキスト、およびリンクのセマンティクスを再読み取りして、直接保存されます。非可逆印刷、電子書籍、および画面プリセットは、明示的な選択肢のままです。
