Convertissez les pages PDF en un HTML propre à mise en page fixe

Le PDF est un format de description de page, et non un contenu Web redistribué ordinaire. ImgIng reconstruit les pages en coordonnées PDF, prend en charge les glyphes de type 3, les images en ligne et masquées, les couleurs ICC et indexées, les motifs de mosaïque, les dégradés axiaux et radiaux et les masques souples courants, puis identifie les cas de révision restants par page.

Prévisualisez, inspectez et enregistrez

Examinez le résultat de mise en page fixe et le rapport de fonctionnalités complexes, puis utilisez la boîte de dialogue d'enregistrement du système pour exporter un fichier HTML.

Pourquoi ne pas promettre que chaque PDF deviendra un HTML ordinaire sans aucune différence de pixel ?

Le PDF stocke les instructions de dessin finales. Le HTML ordinaire redistribue avec les différences de navigateur, de police et de fenêtre d'affichage. L'ombrage de maillage, les mélanges inhabituels, le découpage complexe, les formulaires, la 3D et le multimédia n'ont pas non plus d'équivalent HTML individuel complet. ImgIng utilise donc le SVG à mise en page fixe : les dimensions de la page, les matrices de texte, les chemins vectoriels et les positions des images suivent les coordonnées PDF tandis que le texte reste sélectionnable. Toute fonctionnalité non équivalente est enregistrée dans le rapport par page de l'espace de travail au lieu d'être présentée silencieusement comme une conversion parfaite.

Comment sont reproduits les glyphes, les couleurs, les images et les dégradés complexes ?

ImgIng lit les CharProcs de type 3, met en cache chaque glyphe en tant que symbole vectoriel SVG réutilisable et ajoute un calque de sélection invisible. Il gère les solutions de secours basées sur ICC, les palettes indexées, les images en ligne, les pochoirs ImageMask à un bit, les masques logiciels JPEG et les masques logiciels d'état graphique courants. Les motifs de mosaïque PatternType 1, les ombrages axiaux PatternType 2 et les ombrages radiaux ShadingType 3 deviennent des ressources SVG en ligne sans multiplier par deux la matrice graphique active.

Comment tout peut-il tenir dans un seul fichier HTML épuré ?

Le SVG à mise en page fixe de chaque page, les images, les polices autorisées et le CSS nécessaire sont intégrés. L'exportation n'a pas de moteur d'exécution de visionneuse exécutable, ne contient aucune copie du PDF original et n'ajoute aucune barre d'outils de zoom, de rapport, d'impression ou de fichier original. Ouvrez le fichier et les pages apparaissent immédiatement. Le rapport de qualité reste dans l'espace de travail de conversion pour la comparaison des sources avant d'être enregistré.

Pourquoi les autorisations de police sont-elles vérifiées séparément ?

Une police incorporée dans un PDF ne bénéficie pas automatiquement d'une licence pour être copiée dans un autre document. ImgIng lit le champ fsType OpenType OS/2. Les polices utilisables par le navigateur autorisées pour l'intégration installable, modifiable ou de prévisualisation/impression peuvent être intégrées dans ces limites ; Les polices sous licence restreinte et bitmap uniquement ne sont pas copiées. Cette version ne sous-ensemble pas les polices, utilise une solution de secours sécurisée lorsque l'intégration est interdite et documente la substitution.

Quelle est la limite de sécurité ?

Le convertisseur n'exécute jamais PDF JavaScript, ne transforme jamais les actions PDF en scripts Web et ne conserve que les annotations http, https ou mailto après vérification du protocole. La validation de sortie rejette les chargements de scripts externes, de feuilles de style, d'images ou de polices, et le document généré inclut une politique de sécurité du contenu.

Limites bêta : cette version se concentre sur la lecture, l'archivage, le partage et la reproduction visuelle avec une mise en page fixe, et non sur la conversion automatique d'articles réactifs ou sur un éditeur Web par glisser-déposer. Les groupes isolés ou masqués, les masques dotés de fonctions de transfert spéciales ou de prémultiplication de cache, la couleur d'écran CMJN, le JPEG 2000 multi-navigateur, l'ombrage de maillage, le découpage de texte, les formes complexes et le multimédia peuvent encore nécessiter une révision ; l'espace de travail identifie les pages concernées.

Questions fréquemment posées

Ces réponses visibles correspondent au comportement actuel du produit et aux données structurées.

Le PDF et le résultat sont-ils téléchargés ?

L'analyse, la reconstruction des pages, la vérification des polices, l'aperçu et l'empaquetage HTML se font tous localement.

Le code HTML exporté s'ouvrira-t-il hors ligne ?

Oui. CSS, page SVG, images et polices autorisées sont intégrés ; le résultat ne nécessite aucun serveur ImgIng et ne contient aucune barre d'outils de visualisation.

Pourquoi une police ne peut-elle pas être intégrée exactement ?

Sa licence peut interdire la copie ou autoriser uniquement un mode d'intégration spécifique. ImgIng respecte OpenType fsType, ne contourne pas la licence restreinte et signale la substitution.
