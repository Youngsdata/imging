How can an online designer avoid image uploads?

ImgIng uses browser-native decoding, CSS layer previews and Canvas export. Imported images become local in-memory objects. Moving, scaling and rotating updates GPU-friendly transforms; only the final export redraws every visible layer at the target resolution.

What is this workspace designed for?

It handles product collages, profile and background compositions, social covers, simple poster bases and quick layouts after AI cutout. The first release intentionally focuses on multi-asset composition instead of imitating a complete desktop editor. Crop, text, shapes and colour controls remain clearly labelled roadmap work.

Does the responsive preview reduce export quality?

No. The preview scales to the browser window for smooth interaction, while export uses source images and the actual canvas dimensions. PNG defaults to lossless true colour and can switch to the ImgIng PNG-8 path with 4–256 colours, optional dithering and multi-level alpha. WebP defaults to the calibrated base quality 80, while JPG defaults to 85. Both lossy formats map UI value 100 to encoder quality 99, avoiding disproportionate size with negligible visible gain.

A canvas is limited to 8192 px on either side and 48 megapixels, with up to 24 image layers per design. These explicit limits protect browser memory and responsiveness.

Frequently asked questions

These visible answers match the current product behaviour and structured data.

Does the online designer upload my images?

No. Image decoding, layer previews and final compositing all run in the current browser.

Can I import several images and change their stacking order?

Yes. Every image is an independent layer with move, scale, opacity, bring-to-front, send-to-back, step-up, step-down and delete controls.

Which backgrounds and export formats are supported?

Transparent designs export to PNG or WebP. A solid background also enables JPG. Every format is rendered locally at the target canvas size.
