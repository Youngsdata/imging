Why not promise that every PDF becomes ordinary HTML with zero pixel differences?

PDF stores final drawing instructions. Ordinary HTML reflows with browser, font and viewport differences. Mesh shading, unusual blending, complex clipping, forms, 3D and multimedia also have no complete one-to-one HTML equivalent. ImgIng therefore uses fixed-layout SVG: page dimensions, text matrices, vector paths and image positions follow PDF coordinates while text remains selectable. Any non-equivalent feature is recorded in the workspace per-page report instead of being silently presented as a perfect conversion.

How are complex glyphs, colours, images and gradients reproduced?

ImgIng reads Type 3 CharProcs, caches each glyph as a reusable SVG vector symbol and adds an invisible selection layer. It handles ICCBased fallbacks, indexed palettes, inline images, one-bit ImageMask stencils, JPEG soft masks and common graphics-state soft masks. PatternType 1 tiling patterns, PatternType 2 axial shadings and ShadingType 3 radial shadings become inline SVG resources without multiplying the active graphics matrix twice.

How can everything fit in one clean HTML file?

Each page’s fixed-layout SVG, images, permitted fonts and necessary CSS are inlined. The export has no executable viewer runtime, carries no copy of the original PDF and adds no zoom, report, print or original-file toolbar. Open the file and the pages appear immediately. The quality report remains in the conversion workspace for source comparison before saving.

Why are font permissions checked separately?

A font embedded in a PDF is not automatically licensed for copying into another document. ImgIng reads the OpenType OS/2 fsType field. Browser-usable fonts permitted for installable, editable or preview/print embedding may be inlined within those limits; Restricted License and bitmap-only fonts are not copied. This release does not subset fonts, uses a safe fallback when embedding is forbidden and documents the substitution.

What is the security boundary?

The converter never executes PDF JavaScript, never turns PDF actions into web scripts and retains only http, https or mailto annotations after protocol checks. Output validation rejects external script, stylesheet, image or font loads, and the generated document includes a Content Security Policy.

Beta limits: this release focuses on fixed-layout reading, archiving, sharing and visual reproduction—not automatic responsive-article conversion or a drag-and-drop web editor. Isolated or knockout groups, masks with special transfer functions or matte premultiplication, CMYK screen colour, cross-browser JPEG 2000, mesh shading, text clipping, complex forms and multimedia can still require review; the workspace identifies the affected pages.

Frequently asked questions

These visible answers match the current product behaviour and structured data.

Are the PDF and result uploaded?

No. Parsing, page reconstruction, font checks, preview and HTML packaging all happen locally.

Will the exported HTML open offline?

Yes. CSS, page SVG, images and permitted fonts are inlined; the result needs no ImgIng server and contains no viewer toolbar.

Why might a font not be embedded exactly?

Its licence may prohibit copying or permit only a specific embedding mode. ImgIng respects OpenType fsType, does not bypass Restricted License and reports the substitution.
