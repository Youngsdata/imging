2026-08-20CURRENT
PDFSELF-BUILT ENGINELOCAL

PDF compression that re-encodes each embedded image at its measured DPI

A PDF compression workspace now sits below the video editor entry. The self-built engine parses xref tables, xref streams and object streams locally, walks each page’s content streams while tracking the graphics state matrix, and derives every embedded image’s real effective DPI; only images above the chosen preset are resampled, with Lanczos-3. Each image is classified by ImgIng’s already-calibrated content classifier, then JPEG, indexed-palette Flate, grayscale Flate and keeping the original compete and the smallest wins — with every decision listed. Writing out performs reachability collection, re-deflates uncompressed streams, strips private data and thumbnails, and repacks with object streams; the result is then re-read and reverted if the page count or any page box differs. Screen 72dpi, e-book 150dpi, print 300dpi and lossless-structure presets are available along with a target file size. PDFs and their images never leave the device and no extra runtime is downloaded. Fonts are not subset, so text-only PDFs gain little, and encrypted PDFs, JPEG 2000, JBIG2 and CMYK print JPEGs are left untouched.

PRODUCT STANDARD

Roadmap principles

Every new capability must pass four product rules.

Local first

If a browser can complete the work reliably, image pixels stay on-device.

Results you can trust

Preview, comparison and download share the same real-pixel pipeline.

Large images remain usable

Zooming, panning and editing must stay responsive at high resolution.

Boundaries stay explicit

Planned, device-side, on-demand WASM and server features are labelled separately.

Release and roadmap questions

The same clear answers for people and search engines.

Can I use the future features shown here now?

No. Multi-layer design, professional filters and skin-aware beauty are shipped, while crop, text, shapes, selections and local editing remain planned. Only the Shipped section describes current capabilities.

Will the local image editor upload images?

The shipped Online Design filters keep assets local. The goal is to keep future crop, text, graphics, brush, selections and common-format export in the browser too. Any server-only operation will be labelled before use.

Why publish target dates instead of invented version numbers?

ImgIng currently follows continuous delivery, so dates are easier to verify. Semantic versions can be introduced when the formal release process needs them.

Can the roadmap change?

Yes. Browser support, memory, large-image performance and export parity can change scope; updates will remain visible on this page.
