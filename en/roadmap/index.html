PRODUCT STANDARD

Roadmap principles

Every new capability must pass four product rules.

Local first

If a browser can complete the work reliably, image pixels stay on-device.

Results you can trust

Preview, comparison and download share the same real-pixel pipeline.

Large images remain usable

Zooming, panning and editing must stay responsive at high resolution.

Boundaries stay explicit

Planned, device-side, on-demand WASM and server features are labelled separately.

Release and roadmap questions

The same clear answers for people and search engines.

Can I use the future features shown here now?

No. Only the Shipped section describes the current product. Planned and Research items are not available features.

Will the local image editor upload images?

The goal is to keep crop, colour adjustments, text, graphics, brush, history and common-format export in the browser. Any future server-only operation will be labelled before use.

Why publish target dates instead of invented version numbers?

ImgIng currently follows continuous delivery, so dates are easier to verify. Semantic versions can be introduced when the formal release process needs them.

Can the roadmap change?

Yes. Browser support, memory, large-image performance and export parity can change scope; updates will remain visible on this page.
