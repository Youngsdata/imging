PDF COMPRESSION · SELF-BUILT ENGINE

Compressing a PDF really means compressing every image inside it

Text and vector artwork are already small. What pushes a file into the tens of megabytes is nearly always scanned pages, photos and screenshots. So ImgIng does not attempt a general re-layout — it spends everything on per-image decisions, which is exactly what ImgIng is best at.

  1. 01
    Work out how much resolution each image actually needs

    A 3000-pixel-wide image needs very different resolution filling a page than at business-card size. ImgIng parses each page’s content streams, tracks the graphics state matrix and derives the real placed size, then converts it to effective DPI. Only images clearly above the chosen preset are resampled — with Lanczos-3 rather than bicubic.

  2. 02
    Then pick the genuinely smallest encoding, image by image

    ImgIng reuses the same calibrated content classifier as its image compressor to tell screenshots, illustrations, icons, smooth photos and high-texture photos apart, then races JPEG, indexed palette with Flate, grayscale Flate and keeping the original. The workspace shows every image’s action, before/after size and measured DPI.

  3. 03
    Read the result back before handing it over

    ImgIng walks the object graph from the document root and drops objects left by earlier edits, re-deflates uncompressed streams, strips layout-tool private data and page thumbnails, and repacks with object streams. Finally it re-reads its own output and reverts to your original if the page count or any page box does not match.

Honest limits: ImgIng does not subset fonts, so a text-only typeset PDF usually gains only 5%–20% from structural work and dedicated prepress tools will beat it there. ImgIng’s strong ground is scans, illustrated reports and exported decks — PDFs where images dominate. Encrypted PDFs are detected so you can unlock them first, and JPEG 2000, JBIG2 and CMYK print JPEGs are kept untouched because browsers cannot decode them reliably. Results depend on your file; we do not turn one sample into a universal claim — the workspace tells you image by image what it actually did.

PDF TO HTML · CLEAN SINGLE FILE BETA

Turn the PDF page itself into HTML that opens ready to read

ImgIng does not embed a PDF viewer or hide the source file inside a web page. Its self-built engine parses the document locally, reconstructs the page content as fixed-layout SVG, and exports one HTML containing only the text, graphics, images and permitted fonts needed to read those pages.

  1. 01
    Read the real PDF page structure

    Parse the page tree, resources, content streams, graphics state, font maps, images, paths, links and form appearances instead of taking page screenshots.

  2. 02
    Reconstruct fixed-layout content at the original coordinates

    Normal fonts become selectable text; Type 3 glyphs use their original CharProcs outlines; patterns, axial and radial gradients, images and common soft masks become inline SVG resources.

  3. 03
    Review the quality report, then save the clean result

    The source PDF exists only in the workspace for comparison. Non-equivalent special blending, mesh shading and interactive features are identified with exact page numbers; the final HTML contains neither the report nor an operation menu.

Honest boundary: this is faithful fixed-layout reconstruction, not automatic conversion into a responsive website. Isolated or knockout transparency groups, masks with special transfer functions or matte premultiplication, CMYK screen colour, cross-browser JPEG 2000, mesh shading, text clipping, multimedia and some interactive forms can still require review. The workspace identifies exact pages instead of silently claiming pixel-perfect equivalence.

FREQUENTLY ASKED QUESTIONS

Privacy, formats and local AI

Visible answers match the page’s structured data and current product behaviour.

Does ImgIng upload my images?

Common formats—including JPG, PNG, WebP, GIF and APNG—and local AI cutout run in the browser. Only clearly labelled specialist formats use a server.

Is ImgIng free, and does it add a watermark?

Device-side conversion, compression, animation and AI cutout are free, require no signup and add no watermark.

Which still and animation formats are supported?

ImgIng reads PNG, JPEG, WebP, GIF, BMP, AVIF, HEIC and more, and exports still images plus GIF, APNG, animated WebP and animated AVIF.

Why does local AI download a model?

The model must reach your browser before local inference can run. It is cached where possible and uses WebGPU first, falling back to WASM. Image pixels stay on-device.

Are HEIC reading and AVIF writing also local?

Yes in the full build: libheif and libavif WASM load on demand, then run locally. HEIC writing remains a specialist server capability.

How is ImgIng different from Squoosh or TinyPNG?

Squoosh excels at local still-image codecs; TinyPNG offers cloud compression and APIs. ImgIng integrates local-first stills, animation, HEIC / AVIF and local AI in one interface.

The self-built engine parses xref tables, xref streams and object streams locally, walks each page’s content streams while tracking the graphics state matrix, and derives every embedded image’s real effective DPI; only images above the chosen preset are resampled, with Lanczos-3. Each image is classified by ImgIng’s already-calibrated content classifier, then JPEG, indexed-palette Flate, grayscale Flate and keeping the original compete and the smallest wins — with every decision listed. Writing out performs reachability collection, re-deflates uncompressed streams, strips private data and thumbnails, and repacks with object streams; the result is then re-read and reverted if the page count or any page box differs. Screen 72dpi, e-book 150dpi, print 300dpi and lossless-structure presets are available along with a target file size. PDFs and their images never leave the device and no extra runtime is downloaded. Fonts are not subset, so text-only PDFs gain little, and encrypted PDFs, JPEG 2000, JBIG2 and CMYK print JPEGs are left untouched.
