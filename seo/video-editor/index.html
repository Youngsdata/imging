本地处理并导出

逐帧时序抠像后由 WebCodecs 编码，并把原音频重新封装到 WebM 或 MP4。

为什么视频不能直接把图片抠图模型逐帧运行？

独立处理每帧容易让发丝和半透明边缘在前后帧之间闪烁。图映使用 Robust Video Matting 的循环状态记住时间信息，并在检测到镜头切换时重置状态，以减少边缘抖动与上一镜头残留。

普通 Chrome 都能运行吗？

当前桌面 Chrome 和 Edge 是主要支持目标，需要 HTTPS 或 localhost、安全上下文、WebCodecs 与 WebAssembly。WebGPU 可用时优先使用显卡，不可用时降级 WASM。旧电脑、手机、超长或 4K 视频可能很慢，因此界面会先做能力检测，并持续显示处理进度和预计剩余时间。

为什么提供两个模型？

RVM ResNet50 FP16 默认质量优先，适合发丝和复杂边缘；RVM MobileNetV3 FP16 下载更小，更适合普通机器、较长视频和快速预览。模型按精确字节数与 SHA-256 校验后写入浏览器缓存。

透明视频导出为 WebM VP9 Alpha；MP4 不支持透明通道，适用于纯色、背景图或虚化后的不透明画面。支持文件系统直接写盘的 Chrome 会边处理边写文件，降低长视频内存压力。

常见问题

下列答案与当前产品逻辑和页面结构化数据保持一致。

视频会上传到服务器吗？

不会。完整视频编辑链路在浏览器本地完成，网络只用于首次下载运行库和所选模型。

为什么质量模式处理很慢？

它使用更大的 ResNet50 时序模型，并逐帧解码、推理、合成和编码。速度取决于视频尺寸、时长、帧率与显卡。

导出后原音频还在吗？

默认保留。兼容时直接复制，否则重编码为 WebM 的 Opus 或 MP4 的 AAC 后重新封装。
