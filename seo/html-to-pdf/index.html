单文件直接选择并立即预览；有相对 CSS、图片、字体、脚本或数据文件时选择整个目录。

有 @page 就保留尺寸、方向、边距和分页；没有 @page 就按完整渲染宽高生成一张自定义页面。

03

生成、无损最小化并保存

Chromium 返回真实 PDF 后，通用合并数学等价的重复资源，回读核对页面、文字和链接，再直接写入所选位置。

为什么使用 Chromium，而不是把网页截图成 PDF？

HTML 的最终画面由 CSS 布局、Web 字体、SVG、Canvas、分页规则、链接和浏览器排版共同决定。把 DOM 截成 Canvas 会失去可选择文字、矢量和链接；在 PDF 库里局部重做 CSS 也无法覆盖现代 Web 平台。图映因此复用 Chromium 自己的打印排版与 Skia PDF 输出，返回真实 PDF 字节。

页面为什么不会再被强制变成 A4？

“跟随 HTML 真实页面”是默认策略：检测到 @page 时沿用它的尺寸、方向、边距与分页；没有 @page 的连续网页则读取最终渲染宽高，把完整内容放进一张自定义 PDF 页面。图映 PDF 转 HTML 产物携带逐页尺寸元数据，转换回来时会逐页恢复原来的固定版式，混合尺寸页面也分别保留。A4 与 Letter 只在用户主动选择时应用。

通用无损最小化怎样处理 SVG、Canvas 和字体？

优化器不识别某一种图表库或固定 SVG 模板，而是在 PDF 内容流层分析普通 HTML、SVG、Canvas、中英文字体和混合页面。数学上完全相同的填充路径会变成可复用 PDF Form，调用处的变换、颜色、透明度与裁剪继续原样继承。可见字体完全不动；只有一个 Type 3 字体的每次使用都能证明为不可见、且从未参与文字裁剪时，才把重复字形绘制精简为原始字宽和边界信息。默认也不重采样或重编码任何图片像素。

为什么 PDF 转 HTML 再转回 PDF 仍可能比源文件大？

固定版式 HTML 可能同时保留可见 SVG 轮廓和透明可选择文字层，Chromium 需要重新封装两套信息。无损复用能消除大量重复绘制，但删除其中一层、把矢量栅格化或替换字体都会损失信息；图映不会为了追平源文件字节数这样做。产物会回读核对页数、每页尺寸、文字操作和链接语义，任何不一致都保留 Chromium 原文件。

哪些步骤留在本机，哪些内容会提交？

选择文件、读取获准网页目录、即时预览、映射相对 CSS / 图片 / 字体、隔离运行本地脚本、等待最终画面和 PDF 优化都留在浏览器。点击转换后只提交已经冻结的安全快照；远程资源默认关闭，转换服务禁止外网域名解析，临时文件随请求结束删除。

Beta 边界：连续单页按 Chromium 可稳定输出的页面上限等比例适配；转换快照上限为 64 MB，服务限制并发与 90 秒渲染时长。ES Module 内部相对 import、Service Worker、浏览器扩展页面、跨域登录资源、DRM 媒体和嵌套 iframe 无法保证自动复现；转换前应核对中间预览和质量报告。

常见问题

下列答案与当前产品逻辑和页面结构化数据保持一致。

HTML 和本地资源会立刻上传吗？

不会。导入、目录读取、资源映射和完整预览都在浏览器本地完成；只有点击转换后，去脚本的自包含快照才提交给同源 PDF 服务，临时文件随请求结束删除。

自动最小化会改变图片、SVG 或字体吗？

默认不会。图片像素不重采样，可见中英文字体不变；只复用数学等价的矢量路径，并精简每次使用都能证明不可见的字形绘制。

还需要选择打印机、回选 PDF 或手动压缩吗？

不需要。转换服务返回真实 PDF 后会自动无损最小化并回读页面、文字和链接，再直接写入你选择的位置；打印、电子书和屏幕有损档仍需主动选择。
